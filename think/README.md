# Think — Planos de Solução Compartilhados

Esta pasta preserva o raciocínio técnico e o plano de cada solução proposta
para o projeto. Ela é uma fonte obrigatória de contexto para todos os agentes.

## Regra obrigatória

Antes de tomar decisões ou realizar alterações, todo agente deve ler todos os
arquivos Markdown desta pasta, além das demais documentações obrigatórias do
projeto.

Antes de apresentar um plano para aprovação humana, o agente deve salvá-lo
nesta pasta. A implementação só pode começar após a aprovação explícita.

## Convenção de arquivos

Use o nome `YYYY-MM-DD-HHmm-descricao-curta.md`, com palavras separadas por
hífens. Não altere ou remova planos anteriores: eles preservam o contexto e as
decisões para os próximos agentes.

## Estrutura mínima de um plano

1. Contexto e objetivo.
2. Escopo e arquivos afetados.
3. Etapas de implementação.
4. Impactos, riscos e alternativas consideradas.
5. Estratégia de validação.
6. Status da aprovação humana e resultado.
